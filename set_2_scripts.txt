Consider a schema with three tables representing an online movie streaming service

Movies Table (Movies):

movie_id (NUMBER(10) PRIMARY KEY): Unique identifier for each movie (integer).
title (VARCHAR2(255) NOT NULL): Title of the movie.
release_year (NUMBER(4)): Year the movie was released.
director (VARCHAR2(100)): Director of the movie.
genre (VARCHAR2(50)): Genre of the movie (e.g., Comedy, Drama, etc.).
description (VARCHAR2(4000)): Description of the movie.
duration (NUMBER(4)): Duration of the movie in minutes.


Users Table (Users):

user_id (NUMBER(10) PRIMARY KEY): Unique identifier for each user (integer).
username (VARCHAR2(50) NOT NULL) UNIQUE: Username for login (unique).
email (VARCHAR2(255) NOT NULL) UNIQUE: User's email address (unique).
subscription_type (VARCHAR2(20)): Type of user subscription (e.g., Free, Standard, Premium).


Watchlist Table (Watchlist):

watchlist_id (NUMBER(10) PRIMARY KEY): Unique identifier for each watchlist entry (integer).
user_id (NUMBER(10) FOREIGN KEY REFERENCES Users(user_id)): References the user ID from the Users table.
movie_id (NUMBER(10) FOREIGN KEY REFERENCES Movies(movie_id)): References the movie ID from the Movies table.
added_date (DATE): Date the movie was added to the watchlist.


--CREATE TABLE SCRIPTS
CREATE TABLE Movies (
  movie_id NUMBER(10) PRIMARY KEY,
  title VARCHAR2(25) NOT NULL,
  release_year NUMBER(4),
  director VARCHAR2(25),
  genre VARCHAR2(20),
  description VARCHAR2(40),
  duration NUMBER(4)
);

CREATE TABLE Users (
  user_id NUMBER(10) PRIMARY KEY,
  username VARCHAR2(25) NOT NULL UNIQUE,
  email VARCHAR2(25) NOT NULL UNIQUE,
  subscription_type VARCHAR2(20)
);

CREATE TABLE Watchlist (
  watchlist_id NUMBER(10) PRIMARY KEY,
  user_id NUMBER(10) REFERENCES Users(user_id),
  movie_id NUMBER(10) REFERENCES Movies(movie_id),
  added_date DATE
);
